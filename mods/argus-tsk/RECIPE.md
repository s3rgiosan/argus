# Tasks

The tsk board as a Herdr panel, with the task in a pane beside the terminals. Every read and change goes through the `tsk` CLI; the mod never writes the store.

## What you see

- `mod.json`: `{ "place": "none", "title": "Tasks", "overlay": { "width": 360, "height": 640 }, "panel": { "label": "Tasks", "icon": "icons/list-checks.svg" } }`. The `argus` layout (`scripts/build-layout.mjs`) gives it a toolbar button and a panel. `mod.open` opens it as a 360 × 640 popup.
- One mod, four views picked by `props().view`: none or `"board"` (the panel), `"scopes"` (popup), `"task"` (pane), `"status"` (popup).
- Board, drawn with `ui.js` (a copy of `lib/ui.js`): frame; 42 px header (14 px side padding) with "Tasks" (semibold), the count badge (Herdr's Changes pill: 10 px `muted`, 1 px `border`, radius 4), then on the right the scope button (scope name at 12 px `muted` with a chevron, hover `hover`), the expand button (only in the `argus-panel` column, not in an overlay; `maximize-2`, or `minimize-2` while expanded), refresh (it turns while this copy reads) and settings icon buttons (14 px icons; chevron-down, chevron-left, settings, check, x and square-pen load from Herdr's `mods/workspace-chrome/` folder when it has them, probed once in `init` with `readTextFile`, and from the Lucide copies in `icons/` otherwise); scroll area; bottom bar with a 32 px "New task…" field and an Add button (`solid` while it can run: a title is typed, no add is running, tsk is found).
- Sections, titled like Herdr's group headings (11.5 px, medium, `dim`): "Needs you · n", "In motion · n", "On deck · n" (ready rows, then open rows). Empty sections are left out; no rows and no error shows "No tasks here" ("Loading…" before the first read). The count badge (Herdr's Changes pill) shows after the first read.
- Status popup: `openOverlay({ mod: "argus-tsk", props: { view: "status", owner, number, choices }, kind: "popup", width: 200, height })`, at the pointer, as tall as its rows. One row per choice (Open, Ready, Started, Done; a blocked, review or unknown status adds itself as an extra row) in Herdr's menu metrics (31 px, 8 px side padding, radius 7, 12.8 px text, 5 px around the list): the current one has an `accent` check tick, a disabled one is `dim`. Only the rows that can be picked have a hover background and a pointer. The highlighted row (it starts on the current one) is on `selected`; Up and Down move it, Enter picks it when it can be picked, Escape closes.
- Row, 28 px: an 8 px dot (filled `blocked` for Needs you, filled `working` for In motion, a `muted` ring for On deck), `T<number>` at 12 px `muted`, the title (truncated), the status name at 11 px `dim` (Open, Ready, Started, Blocked, In Review). The selected task's row is on `selected`.
- Scopes popup: `openOverlay({ mod: "argus-tsk", props: { view: "scopes" }, kind: "popup", width: 280, height: 420 })`. Sections: In (Follow space, Desk, All Projects, then each project indented 24 px under All Projects), Threads (Any thread, then each thread) and Assignees (Anyone, then each assignee). Threads and Assignees are left out when they hold only their first row. Each row uses Herdr's menu metrics (31 px) with its count at 11 px `dim` and an `accent` check tick on the current choice of its section (`sidebarModel` in `board.js`). Each count keeps the other choices as they are. A picked project, thread or assignee with no rows left stays in its list. The highlight starts on the first current row; Up and Down move it, Enter picks it, Escape closes, and a click moves it to the clicked row. While a project's rename field shows, the keys belong to the field. A pick sets its own choice and keeps the popup open.
- Project names: the project's tsk title (`project_title`), else its folder name, widened one parent folder at a time while two labels match. Projects sort A-Z by the shown name.
- Rename: with tsk 0.14.0 or newer, each project row ends in a square-pen icon button (Herdr's `square-pen`, a Lucide icon). A click turns the row into a 32 px field, prefilled with the title or else the folder name. Under it: the project's full path (home folder as `~`, truncated) and the hint "Leave empty to use the folder name.", both 11 px `dim`; then Clear (enabled only for a titled project) and Save (`solid`). A refusal shows in 11 px `blocked` under the buttons and the field stays open.
- Settings view: header (14 px side padding) with a back icon and "Settings"; "tsk command" and "Store folder" fields with a hint under each; both save on Enter or when focus leaves.
- Task pane: no frame border (the pane draws one). 42 px header: `T<number>` at 12 px `muted`, the title as a field that shows a border only on hover or focus, then the status dot and name. Scroll body: Notes (textarea, 3 to 12 rows), Status (a 26 px dropdown button, styled like the board's scope button: the current status name at 12 px `muted` and a chevron; then chips for Start Without Agent for an assigned task, Block…, Request Review…, and Relaunch or Start Anyway after those refusals), Assignee field, Runs after (chips that remove a link, a `T#` field that adds one), the block or review form, the open block or review card, Steps (Herdr's Settings switch, text struck out when done, remove icon, "Add a step" field), Activity sentences. Bottom bar: Done (primary; left out on a done task), Reply (blocked or in review; focuses the reply field), Archive.
- Block card: why, "Needs: …", options as chips that fill the reply field, replies, reply field, Answer. Review card: "In Review · Round n", done, checks with a state chip (read-only; `done`, `blocked` or `muted` by state), "Next: …", feedback, reply field, Approve and Send Back. "Waiting on <who>" on the right of the title.

## How it behaves

- `shared` keys: `argus-tsk.board` `{ rows, readAt, error }` (rows from `tsk list --all --json`); `argus-tsk.scope` `{ where: "follow"|"desk"|"all"|"project", project?, thread, assignee }` (none stored follows the space; a scope saved as one `kind` maps onto the new shape in `normalizeScope`); `argus-tsk.selected` `{ number }`; `argus-tsk.settings` `{ tsk, stateDir }`; `argus-tsk.lock` (the reader lock); `argus-tsk.statusPick` `{ owner, number, status, at }` (a status picked in the status popup); `argus-tsk.panelWidth` (the panel width before the last expand); `argus-tsk.paneTitle` (what the `argus-pane` header shows for this mod's panes: `T<number> · <title>` of the shown task from the board, else from the pane's read, `T<number>` while its title is unknown, else "Tasks"; `taskPaneTitle`, written by the task view only when it changes).
- Board and task copies watch the store folder (`watchFolder`, looped in `cx.spawn`). Every tsk run (reads too) changes the store files' metadata, and other tsk clients do the same, so a batch alone proves nothing: after each batch the copy runs `stat` on `tsk.json` (`store.js`: GNU `stat -c "%.9Y %s"` first, then BSD `stat -f "%Fm %z"`, because GNU `stat -f` reads the filesystem; modification time and size) and re-reads only when that stamp moved, 300 ms after the last such change. A watch started again after an empty batch reads once. The copy that takes the lock (`lib/sync.js`, `lib/gate.js`) reads; a copy whose shared board is already newer than the change skips its read. If the watch is refused, the board is read every 10 s.
- Board read: `parseRows` gives null when tsk's output is not a JSON array. A read that exits with 0 and gives null keeps the previous rows and sets the error kind `unexpected` with "tsk printed output that is not a JSON task list.".
- Finding tsk: the tsk command setting, `tsk` on the PATH that Herdr's `exec` sees, then the install locations; the first whose `--version` runs and is 0.13.0 or newer is used, once per setting (a candidate that is too old is skipped, and the "too old" error shows only when no candidate is new enough). Older than 0.13.0 or not found: one note in the panel, no rows. The refresh icon looks again.
- Store folder: the setting (passed to tsk as `--state-dir`), else `TSK_STATE_DIR` read once with `/bin/sh -c 'printf %s "$TSK_STATE_DIR"'`, else `~/.tsk`.
- Follow space: the folder is `focused().cwd`; with a mod pane focused (or no folder), a terminal's folder in the focused tab, then in another tab of the focused space, then the space's folder (`followFolder`). The scope is the board project that is that folder or holds it, on whole folder names, the longest match winning (`followedProject`); no match is the desk (`effectiveScope`). The known projects are the ones that already have tasks on the board, so a folder whose project has no tasks shows the desk. A space on another machine (`machine` set) follows nothing and shows the desk. It is worked out in render from Herdr's live data, so it changes with the focused space, tab and folder. The header reads "Follow space · <name>" and the popup's Follow space row counts the shown rows. Picking Desk, All Projects or a project stops following; picking Follow space starts it again. A thread or an assignee stays set when the place changes.
- Capture runs `tsk add` with the shown scope's target (`captureTarget` in `board.js`: the project, the thread and the assignee of the scope), then re-reads. A refusal shows tsk's message over the bottom bar and keeps the text.
- Rename refuses a title that starts with `-` (`titleError`: "A title cannot start with a dash."), because tsk reads it as an option. Rename runs `tsk project title <path> <title>`, or `--clear` for Clear or an emptied field (`projectTitleArgs`, `titleChange`), then re-reads. Enter saves, Esc cancels, and an unchanged prefill saves nothing. The popup checks `tsk --version` once and shows the square-pen only from 0.14.0 (`TITLES_TSK`).
- Task pane reads `tsk list <n> --json` when the selection changes (seen in render, read in a spawned task), after each write and on store changes. A task tsk does not know, or an archived task (its latest archive entry in the activity is `archived`), shows "Task not found" and clears the selection. Inputs for a task are made after its read, never in render; a re-read refreshes the fields that do not have the keyboard. Title, notes and assignee save on Enter (⌘Return in the notes) or when focus leaves.
- Writes go through `tsk`: status changes (`statusArgs`), title, notes, assignee and runs after (`editArgs`), steps (`stepsArgs`), archive (`archiveArgs`), project titles (`projectTitleArgs`). Status, edits and step toggles and removals show at once (`patchDetail`); a status change also shows on the board. A change to done or an archive clears the selection. A failed write shows tsk's message and re-reads.
- Status dropdown: the pane passes its owner id, the task number and `statusChoices(task)` to the popup. A pick writes `argus-tsk.statusPick` and closes the popup. The pane that opened it sees the pick in render (`statusPick`: same owner, newer than the last pick it handled). It consumes every such pick, even while it loads or shows another task, and for the task it shows runs `changeStatus` in a spawned task with the change `pickedChange` gives, so the optimistic update and the refusal offers work as for the other status writes.
- Expand: the board reads the live layout (`layout()`) for the `argus-panel` column and its width. At or within 20 px of the column's `max` (900) it counts as expanded, so a drag or a restart reads the same. A click on a panel that is not expanded keeps its width in `argus-tsk.panelWidth` and runs `layout.resize { id: "argus-panel", px: <max> }`; on an expanded one it resizes back to that width, else to 368, Herdr's panel width (`panel.js`).
- Answer and Send Back use `flows.js` with `{ reply, setStatus }` built on `runTsk`: one reply, then the status the flow picks. When the reply went out but the status change failed, "Retry Status Change" repeats only the status change.
- Row click: sets `argus-tsk.selected`. If the shown tab has a pane of this mod, `pane.focus` it; else `pane.split { pane: <tab's focused pane>, direction: "right", mod: "argus-tsk", props: { view: "task" } }`.

## Built from

- `main.js`: the `View`; `exec`, `home`, `checking`, `theme`, `shared`, `setShared`, `props`, `run`, `openOverlay`, `closeOverlay`, `panes`, `spaces`, `watchFolder`, `layout`, `focused` from `herdr`; `randomUUID` from `crypto`; `Input` and `Textarea` from `gpui-base`. Every `cx.spawn` body starts with `await cx.sleep(0)`.
- `tsk.js` (argv for every command), `locate.js` (tsk lookup, store folder, version check, settings), `model.js` (JSON to camelCase rows), `board.js` (sections, scopes, the followed project, capture target), `flows.js` (block and review flows), `detail.js` (task read state, status choices and actions per status, status dropdown picks, form changes, optimistic patches), `timing.js` (debounce with an injectable clock), `panel.js` (the panel column's width and the expand button's resize), `store.js` (the `tsk.json` stamp that tells a real store change from read noise). All pure, tested with `node --test`.
- Copies of the files in `lib/`: `ui.js`, `menu.js` (`menuHeight` sizes the scopes and status popups), `icons.js`, `pane.js` (`openModPane`, `shareTitle`, `createInputs`), `follow.js`, `paths.js`, `gate.js` and `sync.js`.

## Watch out

- Herdr's `exec` has no stdin or env options: the store folder goes to tsk as `--state-dir`, placed before a `--` that starts free text.
- `InputState.new` is refused during render. The capture and settings fields are made in `init`. The per-task fields are made in the task read (`bindFields`), the block and review form fields in the click handler that opens the card (`openCard`), and the rename field in the square-pen's click handler (`startRename`).
- A popup is as tall as its content (up to the height asked for): the scopes list sets its height from its rows (31 px each).
- Herdr app 0.1.16 does not load a symlinked mod folder: copy it with `scripts/install.sh`.
