# Tasks

The tsk board as a Herdr panel, with the task in a pane beside the terminals. Every read and change goes through the `tsk` CLI; the mod never writes the store.

## What you see

- `mod.json`: `{ "place": "none", "title": "Tasks", "overlay": { "width": 360, "height": 640 }, "panel": { "label": "Tasks", "icon": "icons/list-checks.svg" } }`. The `argus` layout (`scripts/build-layout.mjs`) gives it a toolbar button and a panel. `mod.open` opens it as a 360 × 640 popup.
- One mod, four views picked by `props().view`: none or `"board"` (the panel), `"scopes"` (popup), `"task"` (pane), `"status"` (popup).
- Board, drawn with `ui.js` (a copy of `lib/ui.js`): frame; 42 px header with "Tasks" (semibold), the scope button (scope name at 12 px `muted` with a chevron, hover `hover`), the count badge (11 px `muted` on `raised`), then refresh and settings icon buttons (14 px Lucide icons in `icons/`); scroll area; bottom bar with a 32 px "New task…" field and an Add button (`solid` while there is a title).
- Sections, titled at 11 px semibold `muted`: "NEEDS YOU · n", "IN MOTION · n", "ON DECK · n" (ready rows, then open rows). Empty sections are left out; no rows at all shows "No tasks here" ("Loading…" before the first read).
- Status popup: `openOverlay({ mod: "argus-tsk", props: { view: "status", owner, number, choices }, kind: "popup", width: 200, height })`, at the pointer, as tall as its rows. One 28 px row per choice (Open, Ready, Started, Done; a blocked, review or unknown status adds itself as an extra row): the current one on `selected` with a check icon, a disabled one at `dim` and not clickable.
- Row, 28 px: an 8 px dot (filled `blocked` for NEEDS YOU, filled `working` for IN MOTION, a `muted` ring for ON DECK), `T<number>` at 12 px `muted`, the title (truncated), the status name at 11 px `dim` (Open, Ready, Started, Blocked, In Review). The selected task's row is on `selected`.
- Scopes popup: `openOverlay({ mod: "argus-tsk", props: { view: "scopes" }, kind: "popup", width: 280, height: 420 })`. Rows: Desk, All Projects, then Projects, Threads and Assignees (section titles left out when empty), each with its count at 11 px `dim`; the current scope on `selected`. A pick sets the scope and closes the popup.
- Project names: the project's tsk title (`project_title`), else its folder name, widened one parent folder at a time while two labels match. Projects sort A-Z by the shown name.
- Rename: with tsk 0.14.0 or newer, each project row ends in a pencil icon button (Lucide `pencil`). A click turns the row into a 32 px field, prefilled with the title or else the folder name. Under it: the project's full path (home folder as `~`, truncated) and the hint "Leave empty to use the folder name.", both 11 px `dim`; then Clear (only for a titled project) and Save (`solid`). A refusal shows in 11 px `blocked` under the buttons and the field stays open.
- Settings view: back icon and "Settings"; "tsk command" and "Store folder" fields with a hint under each; both save on Enter or when focus leaves.
- Task pane: no frame border (the pane draws one). 42 px header: `T<number>` at 12 px `muted`, the title as a field that shows a border only on hover or focus, then the status dot and name. Scroll body: Notes (textarea, 3 to 12 rows), Status (a 26 px dropdown button, styled like the board's scope button: the current status name at 12 px `muted` and a chevron; then chips for Start Without Agent for an assigned task, Block…, Request Review…, and Relaunch or Start Anyway after those refusals), Assignee field, Runs after (chips that remove a link, a `T#` field that adds one), the block or review form, the open block or review card, Steps (16 px check box, text struck out when done, remove icon, "Add a step" field), Activity sentences. Bottom bar: Done (primary; left out on a done task), Reply (blocked or in review; focuses the reply field), Archive.
- Block card: why, "Needs: …", options as chips that fill the reply field, replies, reply field, Answer. Review card: "In Review · Round n", done, checks with a state badge (read-only), "Next: …", feedback, reply field, Approve and Send Back. "Waiting on <who>" on the right of the title.

## How it behaves

- `shared` keys: `argus-tsk.board` `{ rows, readAt, error }` (rows from `tsk list --all --json`); `argus-tsk.scope` (a scope, default the desk); `argus-tsk.selected` `{ number }`; `argus-tsk.settings` `{ tsk, stateDir }`; `argus-tsk.lock` (the reader lock); `argus-tsk.statusPick` `{ owner, number, status, at }` (a status picked in the status popup).
- Board and task copies watch the store folder (`watchFolder`, looped in `cx.spawn`). Every tsk run (reads too) changes the store files' metadata, and other tsk clients do the same, so a batch alone proves nothing: after each batch the copy runs `stat` on `tsk.json` (`store.js`: modification time and size) and re-reads only when that stamp moved, 300 ms after the last such change. A watch started again after an empty batch reads once. The copy that takes the lock (`lib/sync.js`, `lib/gate.js`) reads; a copy whose shared board is already newer than the change skips its read. If the watch is refused, the board is read every 10 s.
- Finding tsk: the tsk command setting, `tsk` on the PATH that Herdr's `exec` sees, then the install locations; the first whose `--version` runs is used, once per setting. Older than 0.13.0 or not found: one note in the panel, no rows. The refresh icon looks again.
- Store folder: the setting (passed to tsk as `--state-dir`), else `TSK_STATE_DIR` read once with `/bin/sh -c 'printf %s "$TSK_STATE_DIR"'`, else `~/.tsk`.
- Capture runs `tsk add` with the scope's target (`captureTarget` in `board.js`), then re-reads. A refusal shows tsk's message over the bottom bar and keeps the text.
- Rename runs `tsk project title <path> <title>`, or `--clear` for Clear or an emptied field (`projectTitleArgs`, `titleChange`), then re-reads. Enter saves, Esc cancels, and an unchanged prefill saves nothing. The popup checks `tsk --version` once and shows the pencil only from 0.14.0 (`TITLES_TSK`).
- Task pane reads `tsk list <n> --json` when the selection changes (seen in render, read in a spawned task), after each write and on store changes. A task tsk does not know, or an archived task (its latest archive entry in the activity is `archived`), shows "Task not found" and clears the selection. Inputs for a task are made after its read, never in render; a re-read refreshes the fields that do not have the keyboard. Title, notes and assignee save on Enter (⌘Return in the notes) or when focus leaves.
- Writes go through `tsk`: status changes (`statusArgs`), title, notes, assignee and runs after (`editArgs`), steps (`stepsArgs`), archive (`archiveArgs`), project titles (`projectTitleArgs`). Status, edits and step toggles and removals show at once (`patchDetail`); a status change also shows on the board. A change to done or an archive clears the selection. A failed write shows tsk's message and re-reads.
- Status dropdown: the pane passes its owner id, the task number and `statusChoices(task)` to the popup. A pick writes `argus-tsk.statusPick` and closes the popup. The pane that opened it sees the pick in render (`statusPick`: same owner and task, newer than the last pick it handled) and runs `changeStatus` in a spawned task with the change `pickedChange` gives, so the optimistic update and the refusal offers work as for the other status writes.
- Answer and Send Back use `flows.js` with `{ reply, setStatus }` built on `runTsk`: one reply, then the status the flow picks. When the reply went out but the status change failed, "Retry Status Change" repeats only the status change.
- Row click: sets `argus-tsk.selected`. If the shown tab has a pane of this mod, `pane.focus` it; else `pane.split { pane: <tab's focused pane>, direction: "right", mod: "argus-tsk", props: { view: "task" } }`.

## Built from

- `main.js`: the `View`; `exec`, `home`, `checking`, `theme`, `shared`, `setShared`, `props`, `run`, `openOverlay`, `closeOverlay`, `panes`, `spaces`, `watchFolder` from `herdr`; `randomUUID` from `crypto`; `Input`, `InputState`, `Textarea`, `TextareaState` from `gpui-base`.
- `tsk.js` (argv for every command), `locate.js` (tsk lookup, store folder, version check, settings), `model.js` (JSON to camelCase rows), `board.js` (sections, scopes, capture target), `flows.js` (block and review flows), `detail.js` (task read state, status choices and actions per status, status dropdown picks, form changes, optimistic patches), `timing.js` (debounce with an injectable clock), `store.js` (the `tsk.json` stamp that tells a real store change from read noise). All pure, tested with `node --test`.

## Watch out

- Herdr's `exec` has no stdin or env options: the store folder goes to tsk as `--state-dir`, placed before a `--` that starts free text.
- `InputState.new` is refused during render. The capture and settings fields are made in `init`. The per-task fields are made in the task read (`bindFields`), the block and review form fields in the click handler that opens the card (`openCard`), and the rename field in the pencil's click handler (`startRename`).
- A popup is as tall as its content (up to the height asked for): the scopes list sets its height from its rows.
- Herdr app 0.1.16 does not load a symlinked mod folder: copy it with `scripts/install.sh`.
