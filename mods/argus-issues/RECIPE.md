# Issues

GitHub issues and GitLab issues as a Herdr panel, with one issue in a pane beside the terminals. Every read goes through `git`, `gh` and `glab`; the mod writes nothing to a forge. New worktree in the pane starts a git worktree for the issue in a local checkout and opens its space.

## What you see

- `mod.json`: `{ "place": "none", "title": "Issues", "overlay": { "width": 360, "height": 640 }, "panel": { "label": "Issues", "icon": "icons/circle-dot.svg" } }`. The `Argus` layout (`scripts/build-layout.mjs`) gives it a toolbar button and a panel.
- One mod, four views picked by `props().view`: none or `"board"` (the panel), `"settings"` (inside the panel), `"scopes"` (popup), `"issue"` (pane).
- Board, drawn with `ui.js` (a copy of `lib/ui.js`): frame; 42 px header with "Issues" (semibold), the count badge, then the scope button (`dropdownButton`, at most 150 px), refresh (spins while this copy reads) and settings icon buttons with tooltips; scroll area; bottom bar with a 32 px filter field.
- Board body, top to bottom: the read notes as error lines (12 px `blocked`); the Mentions me note for GitLab (12 px `dim`); then one section title per group, "<title> · n" (11.5 px, medium, `dim`), each with its rows. Empty states: "Loading…", "No open issues here", "No issues could be read. See the messages above.", "Nothing matches the filter", "Reading this space…", "This space is not a GitHub or GitLab repo.".
- Row (`twoLineRow`): `#n`, the title (truncated), the update age; then "by <author> · <labels>" (truncated) and the assignees on the right (`login` or `login +n`, at most 120 px). The selected issue's rows are on `selected`. A row id is `issue-<group key>-<issue key>`, so an issue in several groups has a row in each.
- Scopes popup: `openOverlay({ mod: "argus-issues", props: { view: "scopes" }, kind: "popup", width: 280, height: 420 })`, drawn with `menuPopup`. Sections Show (Assigned to me, Created by me, Mentions me, All open), In (Follow space, All repos, then each project indented under All repos) and Group by (Repo, Assignee, Label), with `menuRow` rows (31 px, count on the right for Show and In, `accent` tick on the current choice). Height: `menuHeight(rows, 3, { max: 420 })`. Show and In scroll (`parts`), and Group by stays at the bottom (`foot` of `menuPopup`), so it shows with any number of projects.
- Settings view: back header "Settings"; `forgeCommandFields` (gh command and glab command); `intervalPicker` (Refresh every: 1, 3, 5, 10, 15 min); Conversation (segmented: Oldest first, Newest first).
- Issue pane (`detail-view.js` `issuePane`): no frame border. `paneHead`: provider icon, "<repo> · #n", "i of n" with arrow-up and arrow-down icon buttons, the external-link icon button, the title (16 px semibold); a line with the state chip (`done` for Open, `muted` for Closed), a `working` "confidential" chip when set, and "<name> opened 3d ago · updated 2h ago" (12 px `dim`); fact rows (12 px, a 72 px `dim` label): Assignees, Labels (`muted` chips), Milestone when set; an error line for a failed read again.
- Then two folding sections (`foldTitle`), Description and Comments, with a summary on the right ("None" for an empty description, "n comments"). Description is `markdown` or "No description" (`mutedText`). Each comment: `nameLabel` (semibold, login as tooltip), an "internal" chip for a GitLab internal note, the age on the right; then a balloon (radius 8, 1 px `border`) with the Markdown, or "Hidden by GitHub as <reason>." in 12 px `dim`. Comment ids come from `uniqueKeys` of time and author.
- Pane footer (outside the scroll, 1 px top `border`, 12 px sides, 10 px top and bottom): the reason when New worktree cannot start (11 px `dim`), the note of the last start (`note`), the error of the last start (`errorLine`), then the primary button "New worktree" ("Starting…" while it runs; off without a local checkout or while a start runs).

## How it behaves

- `shared` keys: `argus-issues.board` `{ issues, scopes: { assigned, created, mentions, projects }, projects, folders, readAt, notes, listedAt, worked }` (`worked`: the ids of the reads that worked, a project key per project list and `searchRead` per search, which `emptyMessage` checks against `scopeReads`); `argus-issues.scope` `{ show: "assigned"|"created"|"mentions"|"all", where: "follow"|"all"|"project", key? }`; `argus-issues.groupBy` (`"repo"`, `"assignee"` or `"label"`); `argus-issues.selected` `{ key, provider, host, repo, number }`; `argus-issues.settings` `{ interval, conversation }`; `argus-issues.lock` (the reader lock); `argus-issues.paneTitle` (what the `argus-pane` header shows: `#n · <title>`, else "Issues"; a row click and the pane arrows set it from the board row with the selection (`setTitle`), and the pane render keeps it current (`shareTitle`), both from `lib/pane.js`). The gh and glab commands live in the shared key `argus.forge` `{ gh, glab }` (`readForge`, `saveForge` from `lib/forge-settings.js`), shared with `argus-pull-requests`.
- Board sync: `createBoardSync` from `lib/board-sync.js` with the board and lock keys, the failure text "Could not read the issues", `readSettings().interval` and `localFolders(spaces(), panes())`. One copy reads at a time (`lib/gate.js` plus the lock; the lock is written again only when less than half of its time is left). A read that throws leaves one note on the board. Timers: the board reads on open, then every `interval` minutes; every 5 s `watchFolders` probes new folders and forces a read when one holds a project the board does not have.
- Projects: `createForgeRunner` from `lib/forge-runner.js` (`readProjects`): `git rev-parse` and `git remote get-url origin` per folder, grouped by forge repo (`mergeProjects`). A folder that is not a repo or has no remote is probed on each read; a repo after 10 minutes. github.com is GitHub; any other host that is not a known third forge is GitLab.
- A read (`readBoard`): `gh` is looked up always (its searches cover every repo), `glab` only when a GitLab project exists (`locate`). `signedInGitLab` keeps the GitLab projects on gitlab.com, on hosts where `glab auth status --hostname <host>` passes, and on hosts whose check failed for another reason (`glabLoginState` "failed"); a host whose reply says "has not been authenticated with glab" adds "<host>: no glab login for this host" and leaves the board. Only a passed check is kept; the others run again on the next read. `missingNotes` adds the gh or glab missing note. GitHub: the three `gh search issues` calls (`ghSearchArgs`), then `gh issue list` per GitHub project; a repo with issues turned off (`issuesOffList` from `lib/forge-cli.js` as the `recover` option of `attempt`) gives an empty list and no note. GitLab, per host: the username (`glUsername`, kept until refresh), the assigned and created lists (`GL_USER_QUERY`), and `GL_PROJECT_QUERY` per project. Each failure becomes one note (`attempt`); a list of 100 adds a "Showing the first 100 …" note (`limitNote`).
- A project whose list fails keeps the issues of the previous board for `KEEP_LIST_MS` (15 min) after its last good list (`keptLists`, with `listedAt` per project key).
- `assembleBoard` keeps one copy of each issue (the first one read: the Show lists come before the project lists) and the key lists of each Show choice and project. All open in All repos is every issue; All open in a project is that project's list.
- Groups (`buildGroups(issues, by)`, on `groupItems` from `lib/forge-board.js`): issues newest update first (then the higher number); Repo is one group per project key titled with the repo; Assignee is one group per `host/login` titled with the login; Label is one group per lower-case name titled with the first name seen. Groups sort A to Z by title, then key; "No assignee" or "No label" is last.
- Row click: sets `argus-issues.selected`, then `openModPane("argus-issues", { view: "issue" })`: focus this mod's pane in the shown tab, else split the tab's focused pane to the right.
- The pane sees a new selection in render and reads it in a task (`gh issue view` or `GL_DETAIL_QUERY`). A newer read wins. Every 5 s it asks `rereadDue` with `issueSignature` of the board row (update time, state, title, comment count, labels, assignees) against the signature at its last read; with no row it reads after each board read, and with no board copy running it reads once each interval. A failed read again keeps the issue and shows the error under the head.
- ↑ and ↓ select the neighbour in the board's order for the current scope and Group by (`shownOrder`, which counts an issue in several groups once; `positionIn`). The filter text lives in the panel copy, so the pane's position and arrows do not apply it.
- Open in browser and Markdown links: `openInBrowser` from `lib/pane.js` (`cx.open_url`; only http and https open, a failed open shows nothing).
- New worktree (`startWorktree`): `worktreeTarget(board.projects, issue)` gives the board project of the issue's repo when it has a `localPath`, else the reason `NO_CLONE`. `createWorktreeRunner` from `lib/worktree-runner.js` runs `createIssueWorktree(project, { number, title })`: the branch is `issueBranch` (`<number>-<titleSlug>`); a worktree that holds it opens (`space.select` or `space.new`); a local branch of that name gets a worktree with no fetch; a branch of that name only on the remote goes through `branchWorktree`; else the default branch is fetched and the branch is cut from it with `--no-track`; then `space.new { folder }`. The worktree path is `<root>/<repo folder>/<branchSlug>` with the root from Herdr's `settings.json` (`worktrees.directory`, default `~/.herdr/worktrees`). `this.worktreeRuns` holds `{ running, error, note }` per issue key for this pane copy; one start runs at a time; `worktreeState` gives what the footer shows.

## Watch out

- GitLab's root `issues` query is marked as an experiment in GitLab's schema (since 15.6) and needs at least one filter; the assigned and created lists use it.
- GitLab has no mention filter for issues, so Mentions me holds GitHub issues only, with a note when the scope holds a GitLab project.
- GitLab can return fewer discussions than `first` asks for; `pageInfo.hasNextPage` is what tells that the comments were cut.
- `gh issue list` has no `commentsCount`; `gh search issues` has. `gh search issues` gives the state in lower case, `gh issue list` and `gh issue view` in upper case.
- `gh search issues` uses GitHub's search rate limit; a read makes three searches.
- Issue titles, bodies and comments are written by anyone who can open an issue. They are shown only as text or Markdown. The title goes into a branch name only through `issueBranch` (a slug), and `git check-ref-format` checks the name before the worktree starts.
- `InputState.new` is refused during render: the fields are made in `init` (`createInputs`).
- A popup is as tall as its content, up to the height asked for: the scopes list sets its height with `menuHeight`.
- Herdr app 0.1.16 does not load a symlinked mod folder: copy it with `scripts/install.sh`.
